Five ideas, one binary.

Employees are harnesses

Claude Code and Codex run headless in a git worktree of your repository, on your subscriptions. Local models through Ollama, LM Studio or an MLX server serve Shiioo's own loop. Each is one [[employees]] entry; a task goes to the first whose subscription window isn't used up.

The office is one binary

shiioo is the server (the record, the rules, the API and dashboard, the Telegram bot, the workers) and the node that runs the agents, in one process on your machine. Its data is one directory with an embedded database. No Postgres, no containers. Another machine joins with shiioo node and works against the same record.

The record is the only state

Every run is an append-only, hash-chained event log: each model message, tool call, result, rule verdict and approval. Workers hold fenced leases, so a crash, a sleeping laptop or a lost connection means the run resumes from its log, and a side effect never silently happens twice.

Rules first, you second

rules.toml says what agents may do without asking: allow, ask or deny per tool, command, path and repo. Before every tool call the harness asks Shiioo. Most calls are decided at once; the rest wait for your tap. A dead server means deny, never an unguarded agent. At the container level the agent also can't reach hosts you haven't allowed.

Your phone is the interface

Telegram to delegate, approve and be told when something finished or needs you; /plan to hand a goal to the chief of staff, /report for the morning report. A mobile dashboard over Tailscale for the live log, the diff and the buttons. No public address anywhere: the bot long-polls, the dashboard sits on your tailnet.

On the record

Everything an agent did, in order, provably.

A run's log is the thing itself, not a report about it. The worker writes what it is about to do before it does it, so a crash at any point leaves a log that says exactly what did and didn't happen. Each event carries its position, the lease epoch it was written under, and the hash of the event before it; change a byte anywhere and verification fails.

  • Fenced leases. Only the current lease holder can append. A stalled worker that wakes up after a takeover is refused, and so is the late tool call it tries to send.
  • Write before acting. The model's response is recorded before any tool runs; a tool call is recorded as an intent before it is dispatched and as a result after.
  • No blind retries. Pure and idempotent calls are re-run after a crash; a side-effecting call whose outcome is unknown stops the run and asks you.

The staff

Hire the agents you already have.

Claude Code

Driven in its headless print mode, in a worktree of your repo, with the same login you use in the terminal. Every message and tool call is recorded; a crashed worker resumes the very same session. Its five-hour and seven-day windows are read from its output and shown on your phone.

Codex

Driven through codex exec --json with the same approval hook: before each command Codex asks Shiioo, and your rules or your tap decide. Its own OS sandbox is off, because headless Codex can't ask you and its sandbox would block every commit; the hook is the gate, and the container level is the sandbox.

Local models

Shiioo's own agent loop against anything that speaks the OpenAI chat API: Ollama, LM Studio, an MLX server. Name a model ollama/qwen3:32b and it runs on your hardware, for planning, triage and bulk work that shouldn't spend a subscription.

Tasks go to the first employee whose windows are under their limits; /capacity shows what is left this week.

By default an agent runs as your user in its worktree, with no OS sandbox; the rules and your approvals are what stand between it and your machine. Set [isolation] default = "container" and each run gets a Docker container with only its worktree mounted and only the hosts you allow reachable; shiioo secret set keeps the tokens it needs out of the record.

Quick start

Three commands on the Mac, then your phone.

Log in once to claude and/or codex, create a bot with @BotFather, then:

cargo install --path crates/shiioo
export SHIIOO_TELEGRAM_TOKEN=...
shiioo --workspace ~/shiioo-office install

install prints the dashboard link and the Tailscale steps. Put your Telegram id and your repositories in .shiioo/config.toml, restart, and send the bot /run myproject fix the flaky test. The full walkthrough →
