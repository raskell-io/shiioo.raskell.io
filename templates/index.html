01The record

Everything an agent did, in order, provably.

A run's log is the thing itself, not a report about it. The worker writes what it is about to do before it does it, so a crash at any point leaves a log that says exactly what did and didn't happen. Each event carries its position, the lease epoch it was written under and the hash of the event before it. Change a byte anywhere and verification fails.

  • Fenced leases. One worker owns a run at a time, each lease with a higher epoch. A stalled worker that wakes up after a takeover is refused, and so is the late tool call it tries to send.
  • Write before acting. The model's response is recorded before any tool runs; a tool call is recorded as an intent before it is dispatched, and as a result after.
  • No blind retries. Pure and idempotent calls run again after a crash; a side-effecting call whose outcome is unknown stops the run and asks you.

02Rules first, you second

Autonomous by default. Approvals by exception.

rules.toml says what agents may do without asking: allow, ask or deny per tool, command, path and repository. Before every tool call the harness asks Shiioo through a hook. Reads, edits, builds and commits are decided at once; a push, a gh call, an install or a command nobody has seen before waits for your tap. A dead office means deny, never an unguarded agent.

The same gate covers mail: an agent that wants to write to someone asks the office, and the office asks you.

03The desk

Delegate from your phone. Step in from your desk.

On a big screen the office is a desk: what needs you at the top of the sidebar, every run by repository, runs open as tabs and side by side in up to three panes, and a run's log as a conversation, with each tool call one row you can open, the diff of its branch next to the request to push it. Every action has a key, and ⌘K finds any run or command. Most of the time you still delegate. Sometimes the boss walks over and says "no, like this": write to an agent while it works and it reads your message when it finishes its current step; answer a run that waits for you; follow up on a finished one, and a new run picks up the same session on the same branch.

  • Quiet until it needs you. One colour, used only for what waits on you. Working runs get a calm mark, finished ones fade, and a dot shows what finished since you last looked.
  • Talk to an employee. A message goes into the run's log and the agent reads it at its next step. Your rules still apply to whatever it does next.
  • Follow up, don't reopen. A finished run stays closed. A follow-up is a new run that resumes the same Claude Code or Codex session on the same branch, and names the run it continues.

04Where it runs

Your user, a container, or a sandbox. Here, or on the Spark.

At the default level an agent is your user in its own branch. Set a repository to container and each run gets a Docker container with a read-only root, only its worktree mounted, and a network whose only way out is a proxy that admits the hosts you allow. Secrets are references the office resolves at start and redacts from everything it records.

05A day at the office

You set direction. The company does the work.

The morning report counts what finished, what needs you and which branches await review. /plan hands a goal to the chief of staff, who reads the repository and proposes work items; your approval turns them into issues the office works through. Routines run on a schedule you can type. Files a run produced land on your phone; mail goes out only after you say so.

06The staff

Hire the agents you already have.

Claude Code

Driven headless in its print mode, in a worktree of your repo, with the same login you use in the terminal. Every message and tool call is recorded; a crashed worker resumes the very same session. Its five-hour and seven-day windows are read from its output and shown on your phone.

Codex

Driven through codex exec --json with the same approval hook: before each command Codex asks Shiioo, and your rules or your tap decide. Its own OS sandbox is off because headless Codex can't ask you and its sandbox blocks every commit; the hook is the gate and the container level is the sandbox.

Local models

Shiioo's own agent loop against anything that speaks the OpenAI chat API: Ollama, LM Studio, an MLX server. Name a model ollama/qwen3:32b and it runs on your hardware, for planning, triage and bulk work that shouldn't spend a subscription.

The chief of staff

Not a model, a role the office plays: /plan runs a read-only planning job and turns its answer into a plan you approve; the report, the routines and the capacity broker decide who works when. Runs that wait for your reply and messages to a working agent are built; voice notes and a chief of staff you talk to while walking are next.

Tasks go to the first employee whose subscription windows are under their limits; /capacity shows what is left this week.

By default an agent runs as your user in its worktree, with no OS sandbox; the rules and your approvals are what stand between it and your machine. Set [isolation] default = "container" and each run gets a Docker container with only its worktree mounted and only the hosts you allow reachable.

08Quick start

Three commands on the Mac, then your phone.

Log in once to claude and/or codex, create a bot with @BotFather, then:

cargo install --path crates/shiioo
export SHIIOO_TELEGRAM_TOKEN=...
shiioo --workspace ~/shiioo-office install

install prints the dashboard link and the Tailscale steps. Put your Telegram id and your repositories in .shiioo/config.toml, restart, and send the bot /run myproject fix the flaky test. The full walkthrough →
